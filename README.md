# ミライ花火

> その一発は、未来まで届くか。

長岡花火をモチーフにした、打ち上げ高度を競うブラウザゲームです。
**新潟デジコングランプリ 出展作品。**

**▶ 遊ぶ： https://11kawauso.github.io/Mirai-Hanabi/**

ライブラリなし・ビルドなしのバニラ実装です。`index.html` をブラウザで開けばそのまま動きます。

---

## 作品について

新潟県長岡市で毎年8月2日・3日に開かれる「長岡まつり大花火大会」は、日本三大花火大会のひとつです。
1945年8月1日の長岡空襲で亡くなった方への慰霊と、戦災からの復興への願いが込められた花火大会で、
名物の**正三尺玉**や、中越地震からの復興を願って打ち上げられる**フェニックス**が知られています。

「どこまで高く打ち上がるか」を追いかけるこのゲームは、**その願いを未来へ届けるイメージ**から作りました。
タイトルの「ミライ」はそこから来ています。

---

## 遊び方

砲台から打ち上がった花火を操作して、雲・破片・鳥を避けながら、少しでも高くを目指します。

| 操作 | |
|---|---|
| スマホ | 画面下のボタン／スティック（切替ボタンで変更） |
| PC | <kbd>←</kbd><kbd>→</kbd> または <kbd>A</kbd><kbd>D</kbd> ／ <kbd>↑</kbd><kbd>↓</kbd> または <kbd>W</kbd><kbd>S</kbd> |

上下に動ける幅はごくわずかで、基本は左右で避けます。左右のピンクの壁に触れるか、障害物に当たると開花して終了です。

打ち上げから約3秒後、画面下に**風**のゲージが出ます。矢印の向きへ勝手に流され、数十秒ごとに向きと強さが移り変わります。
5,000mから強風、15,000mから暴風が吹くようになり、風速5m/sを超えると風上からゴミが飛んできます。

10,000mからは**積乱雲**が現れます。ぶつかっても壊れませんが厚みが500mほどあり、抜けるまで画面全体が白くかすみます。
中にはところどころ濃いモヤの層があり、そこだけさらに見通しが落ちます。

到達高度に応じて花火スキンが解放されるほか、**花火問屋**（ガチャ）で限定のスキン・背景・トレイルを仕入れられます。

## 工夫した点

### 高リフレッシュレート環境での描画最適化

検証に使った環境が **240Hz** で、1フレームの持ち時間が **4.2ms** しかありませんでした。
60Hzなら問題にならない描画コストがそのまま破綻に直結するため、毎フレームの塗り面積と `stroke()` 回数を削る作業を重ねています。

- **背景グリッド**（[script.js:1941](script.js#L1941)）— 斜めのアンチエイリアス線を含む約48本を毎フレーム `stroke()` していたことが原因で、飛行中に300〜425msの詰まりが出ていました。線の絵は地平線が動かなければ同じなので、裏canvasへ描いて貼る方式に変更。地平線は5,450mかけて344pxしか動かないため、作り直しは16mに1回で済みます。
- **火花の光彩**（[script.js:2404](script.js#L2404)）— 30,000m級の玉は数百個の粒を撒きます。1粒ごとに `shadowBlur` と `save/restore` を掛けるのは破滅的なので、色ごとに光彩を焼いたスプライトを作り、1粒＝`drawImage` 1回に。
- **星の明滅**（[script.js:2043](script.js#L2043)）— 70個の星を1個ずつ塗ると、色文字列の解釈とパス構築を毎フレーム70回分捨てることになります。明滅の濃さを8段に丸め、同じ段の星を1本のパスにまとめました。

### スキップ券の速度曲線

[script.js:17](script.js#L17)

券を使った回は、指定の高度まで一気に駆け上がる演出が入ります。
当初は「打ち上げ」と「駆け上がり」を別々の段にしていましたが、砲口の蹴りが減衰しきったところへ急加速が来るため、撃たれたあとに一拍もたつく画になりました。

そこで**速度を差し替えるのではなく、通常の打ち上げに山を足す**形に変更しています。
出だしは通常の打ち上げと数値まで同一で、蹴りが衰え切る前に山が立ち上がり、着地時には山が0に戻って巡航速度ちょうどで着きます。
山は smootherstep の微分なので値も傾きも両端で0になり、足しても継ぎ目が出ません。
位置は closed form で決めているので、目標高度をきっかり踏みます。

### ランキングの保護

[RANKING-SETUP.md](RANKING-SETUP.md)

認証なしの公開データベースですが、書き込みルールで
`newData.child('score').val() >= data.child('score').val()`
を要求しているため、**既存の記録を下げる方向の書き込みができません**。
名前は1〜12文字の文字列であることを `.validate` で検証しています。
各ルールの意図はセットアップ手順書に表でまとめてあります。

### 端末まわりの細かい対応

- **文字数の数え方**（[index.html:135](index.html#L135)）— `maxlength` はUTF-16単位を数えるため、`𠮟` のようなサロゲートペアの漢字を2文字と数えてしまいます。HTML側は緩めに取り、JavaScript側で12「文字」として掛けています。
- **画面の向き**（[index.html:14](index.html#L14)）— `screen.orientation.lock` は全画面時のみ有効で、iOS Safariは非対応です。タブ内では向きを本当に固定できないため、横になったら盤ごと覆ってゲームを止め、縦に戻すと続きから遊べるようにしています。
- **入力方式による有利不利をなくす** — スティックのアナログ入力は、ボタン／キーと同じ最高速度に正規化しています。ランキングを競う以上、操作方法で速度が変わってはいけないためです。

## ファイル構成

```
index.html          画面構造と、遊び方・長岡花火の解説パネル
script.js           ゲーム本体（描画・物理・ガチャ・ランキング）
style.css           レイアウトとUI
RANKING-SETUP.md    Firebase Realtime Database の設定手順
```

`script.js` 全体が単一のIIFEで、グローバルを一切汚しません。
先頭に調整用の定数がまとまっているので、挙動を追うならそこからが読みやすいと思います。
